🚗 C# and OOP

Remember OOP using a car: blueprint, real car, hidden engine, and common driving contract.

1. What is a class and an object?

📐 Blueprint vs 🚗 real car
Class → creates → Object
One-line: A class is a blueprint; an object is its runtime instance.
Interview answer: A class defines data and behavior, while an object is an allocated instance of that class.

2. What is encapsulation?

🚗 Engine hidden under bonnet
Private State → Public Methods
One-line: Encapsulation protects state and exposes controlled behavior.
Interview answer: I keep fields private and expose operations through methods or properties so callers cannot create an invalid state.

3. What is abstraction?

🎛️ Steering wheel hides mechanics
Caller → Contract → Hidden Implementation
One-line: Abstraction shows what an object does and hides how it works.
Interview answer: Interfaces and abstract types expose essential behavior while hiding implementation complexity.

4. What is inheritance?

🌳 Child inherits family features
Base Class → Derived Class
One-line: Inheritance lets a derived class reuse and specialize a base class.
Interview answer: It models an is-a relationship, although I prefer composition when behaviors must vary independently.

5. What is polymorphism?

🔌 Same socket, different devices
Interface → Implementation A / B / C
One-line: One contract can execute different implementations.
Interview answer: Runtime polymorphism is commonly achieved through interfaces or virtual method overriding.

6. Interface vs abstract class?

📜 Contract vs 🏠 parent house
Interface = capability | Abstract = shared base
One-line: An interface defines a contract; an abstract class can share state and implementation.
Interview answer: I use interfaces for loose coupling and capabilities, and abstract classes for closely related types with common behavior.

7. Overloading vs overriding?

🚪 Multiple entrances vs rebuilt room
Same name + different parameters | Base → Derived
One-line: Overloading changes parameters; overriding replaces inherited virtual behavior.
Interview answer: Overloading is compile-time polymorphism, while overriding is runtime polymorphism.

8. Value type vs reference type?

📦 Value vs 🏷️ address card
Value copied | Reference copied
One-line: Value types contain data directly; reference types point to objects.
Interview answer: Assignment copies a value for value types, while reference-type assignment normally copies the reference.

🏗️ SOLID and Design Patterns

SOLID is a stable building. Patterns are reusable floor plans.

9. Single Responsibility Principle?

👷 One employee, one job
Type → One focused reason to change
One-line: A class should have one focused responsibility.
Interview answer: I separate responsibilities that change for different business reasons.

10. Open Closed Principle?

🔌 Add plug-in, do not rewire
Stable Core + Extension
One-line: Software should be open for extension and closed for unnecessary modification.
Interview answer: I extend behavior through strategies, interfaces, or composition rather than repeatedly changing stable code.

11. Liskov Substitution Principle?

🔁 Replace without surprise
Base Contract ⇄ Valid Subtype
One-line: A subtype must preserve the expectations of its base contract.
Interview answer: Replacing the base type with a subtype should not break behavior or invariants.

12. Interface Segregation Principle?

🍽️ Small menu
Large Interface → Focused Interfaces
One-line: Clients should depend only on methods they actually use.
Interview answer: I split large interfaces into role-specific contracts to avoid forcing unrelated members on consumers.

13. Dependency Inversion Principle?

🎮 Remote depends on protocol
Business Logic → Interface ← Infrastructure
One-line: High-level logic should depend on abstractions, not concrete details.
Interview answer: Business logic and infrastructure communicate through contracts, improving testability and substitution.

14. Factory, Strategy, and Decorator?

🏭 Create, 🗺️ choose, 🎁 wrap
Factory = creation | Strategy = algorithm | Decorator = behavior layer
One-line: Factory creates, Strategy selects behavior, and Decorator adds behavior.
Interview answer: I choose the pattern based on the source of variation rather than applying patterns automatically.

🧊 Fixed tray vs expandable shelf
Fixed length | Dynamic length
One-line: An array has fixed length; List<T> resizes dynamically.
Interview answer: I use arrays for fixed-size data and List<T> for general dynamic collections.

16. Dictionary vs List?

📖 Index vs shelf scan
Key → Value | Ordered items
One-line: Dictionary supports key lookup; List stores ordered items.
Interview answer: For repeated key lookup I prefer Dictionary; for ordered iteration I use List.

17. Queue vs Stack?

🎫 Ticket line vs 🍽️ plates
FIFO | LIFO
One-line: Queue is first-in-first-out; Stack is last-in-first-out.

18. IEnumerable vs IQueryable?

🏠 Local chef vs restaurant order
.NET iteration | Provider expression → SQL
One-line: IEnumerable iterates in .NET; IQueryable builds provider-translatable queries.
Interview answer: With EF Core, I keep filtering as IQueryable until query composition is complete, then materialize once.

19. Deferred execution?

📝 Recipe runs when cooked
Define Query → Enumerate → Execute
One-line: Many LINQ queries execute when enumerated, not when declared.
Interview answer: I materialize with ToList when I need a stable snapshot or must avoid repeated execution.

20. Delegate vs event?

📞 Phone number vs 🔔 controlled doorbell
Delegate = method reference | Event = publisher notification
One-line: A delegate references methods; an event restricts invocation to the publisher.
Interview answer: Events provide controlled publisher-subscriber communication built on delegates.

25. What is a deadlock?

26. Garbage collection generations?

🌱 Young → mature → old

27. What causes a managed memory leak?

🧱 .NET and .NET Core Fundamentals

Remember .NET as a managed factory: source code becomes IL, the CLR manages execution, and the JIT produces machine code.

53. What is .NET?

🏭 Managed application factory
Languages + Runtime + Libraries + Tools
One-line: .NET is a cross-platform developer platform with a runtime, libraries, languages, and tools.
Interview answer: I use .NET to build web, cloud, desktop, worker, and service applications with managed execution and a common base library.

54. .NET Framework vs modern .NET?

🏠 Windows-only old house vs 🌍 modern portable building
.NET Framework = Windows | Modern .NET = Cross-platform
One-line: .NET Framework is the older Windows-focused platform; modern .NET is cross-platform and actively developed.
Interview answer: For new development I normally choose modern .NET, while .NET Framework remains relevant for existing Windows-specific applications.

55. What are CLR, CTS, and CLS?

🏭 Manager, common catalog, common rulebook
CLR = execution | CTS = types | CLS = language rules
One-line: CLR runs managed code, CTS defines types, and CLS defines interoperable language rules.

56. What are IL and JIT?

📝 Universal recipe translated by local chef
C# → IL → JIT → Machine Code
One-line: C# compiles to IL, and JIT converts IL into native code at runtime.
Interview answer: The assembly contains IL and metadata; the runtime compiles required methods for the current platform.

57. SDK vs Runtime?

🧰 Builder toolbox vs ▶️ execution engine
SDK = build and develop | Runtime = run
One-line: The SDK builds applications; the runtime executes them.
Interview answer: Development machines need the SDK, while a target needs an appropriate runtime unless the application is self-contained.

58. What is an assembly?

📦 Versioned application package

One-line: An assembly is a compiled deployment and versioning unit.
Interview answer: It contains IL, metadata, a manifest, and optionally embedded resources in a DLL or executable.

59. Managed vs unmanaged code?

👮 Runtime-supervised vs direct machine access
Managed → CLR | Unmanaged → Native OS
One-line: Managed code runs under CLR services; unmanaged code executes outside CLR management.

60. Framework-dependent vs self-contained deployment?

🏨 Use installed kitchen vs 🎒 carry your own kitchen
Shared Runtime | App + Runtime
One-line: Framework-dependent uses an installed runtime; self-contained ships the runtime with the app.
Interview answer: Self-contained improves deployment independence but increases package size and runtime servicing responsibility.

🧠 Advanced C# Language

These questions cover common senior-level language details missing from the original artifact.

61. const vs readonly vs static readonly?

🪨 Engraved, sealed at construction, shared sealed value
Compile time | Instance runtime | Type runtime
One-line: const is compile-time; readonly is assigned during construction; static readonly is shared per type.
Interview answer: I use const only for true compile-time constants and readonly for runtime values that should not change afterward.

62. ref, out, and in parameters?

📦 Read/write box, output box, read-only box
ref = read/write | out = assign output | in = read-only reference
One-line: They pass variables by reference with different initialization and mutation rules.
Interview answer: I use them sparingly because normal return values are usually clearer.

63. String vs StringBuilder?

🧊 Immutable ice block vs 🧱 reusable construction board
String changes → new object | Builder mutates buffer
One-line: String is immutable; StringBuilder is efficient for repeated modifications.
Interview answer: For a few concatenations normal strings are fine; for loops or many edits I consider StringBuilder.

64. throw vs throw ex?

🪜 Preserve original ladder vs restart ladder
throw = preserve stack | throw ex = reset stack origin
One-line: Use throw to rethrow while preserving the original stack trace.
Interview answer: I add context only when useful and preserve the original exception as the inner exception.

65. What are generics?

📦 One reusable box design for many item types
Generic<T> → Type-safe reuse
One-line: Generics provide type-safe reusable code without object casting.
Interview answer: They improve reuse, compile-time safety, and often avoid boxing for value types.

66. What are extension methods?

🧩 Add an external tool to an existing toolbox
Static Method + this parameter → instance syntax
One-line: Extension methods add instance-like syntax without modifying the original type.
Interview answer: They are static methods resolved at compile time and should be discoverable and focused.

67. What does yield return do?

🚰 Deliver one item at a time
Iterator → yield → next item on demand
One-line: yield return creates a lazy iterator without building the full collection first.
Interview answer: The compiler creates a state machine that resumes iteration when the consumer requests the next item.

68. Shallow copy vs deep copy?

📄 Copy address cards vs copy houses too
Shallow = nested references shared | Deep = independent graph
One-line: Shallow copy shares nested references; deep copy duplicates the required object graph.
Interview answer: Deep copying must be explicitly designed because identity, cycles, and external resources make generic copying risky.

Interview answer: I choose by access pattern rather than assuming one concurrent collection solves every synchronization problem.

102. What is Channel<T>?

📨 In-process producer-consumer conveyor
Producer → Bounded Channel → Consumer
One-line: Channel<T> supports asynchronous producer-consumer pipelines.
Interview answer: A bounded channel provides backpressure so producers do not overwhelm consumers.

103. What is ThreadPool starvation?

👷 Every worker is blocked, new jobs wait
Blocking work → Workers exhausted → Queue grows → Latency rises
One-line: ThreadPool starvation happens when available worker threads cannot service queued work promptly.
Interview answer: I look for blocking calls, sync-over-async, long CPU work, lock contention, queue growth, and thread metrics.

104. lock vs SemaphoreSlim?

🔑 One room key vs 🎟️ limited entry passes

One-line: lock protects a synchronous critical section; SemaphoreSlim limits concurrent access and supports WaitAsync.

🏗️ Oversized warehouse section
